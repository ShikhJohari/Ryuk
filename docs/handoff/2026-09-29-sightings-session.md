## What exists now

- **Ranking** (`ryuk.watchlist.live`). `WatchlistEmbeddings.ranking(probe, rule) -> Ranking | None` gives the top two persons of interest (`Ranking(top, runner_up)`, runner-up None with one person); `top_candidate` is gone. The rule dispatch is `_scores(probe, rule)`, unchanged in shape so #28 adds rule cases there. `live.Match` carries `runner_up`, never sent on the wire.
- **The tracker** (`ryuk.watchlist.tracker`). A pure `SightingTracker` (no database, no I/O, time passed in): confirmation over 500 ms (at least 3 frames and at least half), several faces of one person in a frame counting once, best crop by strict maximum with the runner-up from the same frame, the 3 s gap checked on frames and on `tick(now)`, `ended_at = last_seen_at`, one write per second per sighting plus a final one. `observe`, `tick`, `end_person`, `end_all`, `clear_runner_up`, `snapshot`/`restore`. Changes are `Opened`, `Updated`, `Ended`; crops are cut with a 25% margin (`cut_crop`) and held as pixels until written.
- **Monitoring** (`ryuk.watchlist.monitoring`). `MonitoringSessions` keeps one tracker per live-monitor connection, under the Watchlist's lock and on its injected clock: `begin`, `end`, `observe`, `tick`, `end_person`, `end_all`, `purge`, and `all_or_nothing()`, which snapshots every tracker and restores them if the transaction fails. A session whose close-time end fails becomes an orphan: every later write (a new session starting, any frame or tick) ends its sightings first in the same transaction and forwards the `sighting_ended` to the live connection, so a person never has two open rows. `write(session, changes)` turns changes into store writes and `SightingAnnouncement`s; crops are JPEG q95 (`CROP_QUALITY`, the stored-photo policy, #47 Q9).
- **Store** (`ryuk.watchlist.sightings`). `open_sighting`, `update_sighting`, `end_sighting` (all joining the caller's session), `end_open_sightings` (the startup rule, called in `start_watchlist`), `sighting_page` with an opaque cursor (`started_at DESC, id DESC`), `get_sighting`, `sighting_crop`, and `summarise`, the one builder of a summary for a row or a live sighting.
- **Table** `sighting` (migration 0003): `person_id` cascades; `model_key` is a plain column, not a foreign key (T1: `_sync_embeddings` deletes `recognition_model` rows); `runner_up_person_id` is set null on purge, `runner_up_score` kept; `best_crop` BLOB (deferred); index on `(started_at, id)`.
- **Watchlist** (`ryuk.watchlist.service`). `update_person(id, *, name=None, status=None) -> PersonChange` (removal ends the person's open sighting in the same transaction), `purge(id)` (one transaction: runner-up references cleared explicitly, then the person, photos, embeddings and sightings cascade; open sightings announced ended without a write), `activate` ends every open sighting when the model actually changes, `recognise(frame, session) -> LiveFrame`, `tick(session)`, `begin_monitoring`/`end_monitoring`, and the sighting reads. `set_status` and `rename` are gone.

## Patterns later tickets should copy

- **Everything in the earlier lists still holds.**
- **Pure core, thin adapter.** The tracker decides; `monitoring.write` persists and announces. Test the rules on the pure core with time passed in, and the wiring once through the socket.
- **In-memory state beside a transaction is snapshotted.** Anything held in memory that a transaction also changes (the trackers here) is snapshotted before and restored if the commit or the embeddings reload fails; test it by failing the commit with a `before_commit` hook.
- **Time-driven rules need a tick, not the next frame** (#47 Q18): the tab stops sending frames while hidden.
- **Carry the target in the mutation's variables.** The router reuses a route component across `/watchlist/a` → `/watchlist/b`; an Undo or a rename that read the id from the render would act on the wrong person. The person page is also keyed by person.
- **Parallel agents get separate worktrees.** Three implementers in one tree would race on the index; each worked on its own branch and the lead merged (`--no-ff`), keeping commit hashes stable for a peer session that cherry-picked one.
